# Gateway adapter (unverified on physical hardware)
Run the inventory script only on a managed OpenWrt device with explicit administrative authorization. It prints leases and station data locally; it is not a fingerprinting or tracking mechanism. Randomized MAC addresses must not be linked to marketing identity. The inventory may be incomplete on unsupported chipsets/routers. Do not upload raw output.

For cloud aggregate reporting, provision a dedicated non-anonymous Supabase Auth user and explicitly bind its UUID to the intended tenant and site in pandora_connect.gateway_bindings. Never give it a business membership or a service-role credential. The owner must provide the verified tenant and site identifiers. Store the short-lived access token in the bridge's protected environment; renew it through an approved credential broker. The reference CLI takes two measured nonnegative integer arguments, connection observations and bytes transferred during the five-minute reporting window. Do not submit invented measurements. Use the same window for retry; updates replace rather than increment counts. Observations are not unique people. The CLI is not a background scheduler; scheduling, rotation, measured byte deltas, gateway network access and secure local retention require hardware commissioning.

Run `node gateway/send-window.mjs <connection-observations> <bytes-transferred>` with the documented environment variables in a protected local environment. No real gateway has been provisioned. The router's Wi-Fi access is unaffected.
